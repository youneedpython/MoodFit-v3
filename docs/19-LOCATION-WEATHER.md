# 위치 / 날씨 자동 입력과 지역 표시 — TASK-035 / TASK-040

2026-10-04 Human이 승인한 Frontend 기능이다. 기존 Check-in 요청에는 기온과 날씨 조건만 전달한다.

## 사용자 동작

- 저장 설정이 없으면 **자동** 모드로 진입하고 위치 조회를 시작한다. 브라우저가 필요할 때 권한을 묻는다. 기존 `moodfit.autoWeather=false`는 **직접 입력**을 유지한다. 권한 유지 기간은 브라우저 정책에 따른다.
- 자동 모드는 지역 · 날씨 · 기온 요약과 **다시 조회** / **직접 입력** 버튼을 표시한다. 직접 입력 모드는 기존 기온 / 날씨 입력과 **자동으로 가져오기** 버튼을 표시한다. 선택한 모드는 기존 키에 boolean 문자열만 저장한다.
- 위치 / 날씨 조회 실패나 시간 초과는 이유를 알리고 직접 입력 화면으로 전환한다. 저장된 모드는 유지해 다음 방문에 다시 자동 시도한다. 권한 거부만 직접 입력 설정을 저장한다.
- 지역 이름 조회 실패 / 잘못된 응답 / 시간 초과는 **현재 위치**로 대체하고 날씨를 채운다. 위치, 날씨와 지역 이름 요청은 각각 최대 10초다. 조회 상태는 `aria-live`, 실패는 `alert`, 진행·성공은 `status`로 알린다.
- 직접 입력으로 바꾸면 조회된 기온과 날씨를 유지한다. 진행 중 요청을 중단하고 늦은 응답을 무시하여 직접 입력을 보호한다. 저장 중에도 조회를 중단한다. 자동 모드에 값이 없으면 기존 제출 검증 안내를 표시한다.
- 저장소 접근이 제한되면 직접 가져오기는 사용할 수 있지만 다음 방문의 자동 조회 설정을 기억하지 못할 수 있다.

## 개인정보

DEC-033에 따라 위도·경도를 소수 둘째 자리로 반올림한다(약 1km, 경도 간격은 위도에 따라 달라짐). 범위 검사를 유지하며 같은 좌표를 Open-Meteo 날씨 API와 BigDataCloud 지역 이름 API에만 보낸다. 두 서비스는 반올림 좌표와 통신 IP를 수신한다. 외부 요청은 `credentials: "omit"` / `referrerPolicy: "no-referrer"`를 사용한다. 좌표와 지역 이름은 화면 메모리에서만 사용하고 Backend / 브라우저 저장소 / 로그에 저장하지 않는다. Backend 요청에는 기존 기온과 날씨 종류만 포함한다.

## 지역 이름 API / 이용 조건

[BigDataCloud 공식 Client API 문서](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api)를 2026-10-04 확인했다. `https://api.bigdatacloud.net/data/reverse-geocode-client`에 반올림한 `latitude`, `longitude`와 `localityLanguage=ko`만 전달한다. 위치 권한이 없으면 좌표 없는 IP 기반 조회로 대체하지 않는다.

공식 문서는 무료 / API Key 없음, 브라우저나 모바일 Client 직접 호출, 표준 위치 API의 현재 장치 위치 사용, 저장된 좌표 / 제삼자 좌표 / 서버 / 일괄 조회 금지를 안내한다. 제공자는 좌표와 IP의 조합을 IP 위치 정확도 개선에 사용한다고 설명한다. 상세 Fair Use / 개인정보 보존 기간 / 상업 사용 세부 조건과 소수 둘째 자리 반올림 허용에 대한 명시적 문구는 **확인 필요**다. 확인하지 않은 조건을 보장하지 않는다.

`principalSubdivision`과 `locality`는 문자열만 허용하고 공백 제거 후 각 40자로 제한한다. 빈 값과 중복은 제거하며 모두 없으면 현재 위치로 표시한다. React 기본 escaping으로 출력하고 HTML을 삽입하지 않는다. 지역 요청은 날씨와 병행하며 독립적인 10초 제한과 AbortSignal을 사용한다. 실패해도 날씨 조회 성공을 유지한다.

## API / 변환

[Open-Meteo Forecast 문서](https://open-meteo.com/en/docs)의 `current=temperature_2m,weather_code`를 요청하며 섭씨를 명시한다. 외부 응답의 숫자 타입·유한 기온·범위·WMO 코드를 검증한 뒤 기온을 소수 첫째 자리로 반올림한다. 원래 기온이 -30 ~ 50°C를 벗어나면 두 칸 모두 채우지 않는다.

| WMO 코드 | 기존 조건 | 대응 근거 |
|---|---|---|
| 0, 1 | CLEAR | 맑음 / 대체로 맑음 |
| 2, 3, 45, 48 | CLOUDY | 부분 흐림 / 흐림 / 안개 |
| 51, 53, 55, 56, 57, 61, 63, 65, 66, 67, 80, 81, 82, 95, 96, 99 | RAIN | 이슬비 / 비 / 소나기 / 뇌우를 강수 조건으로 묶음 |
| 71, 73, 75, 77, 85, 86 | SNOW | 눈 / 싸락눈 / 눈 소나기 |

범위 사이의 미정의 코드도 거부한다. 안개·뇌우 등 세부 상태는 기존 4개 조건으로 단순화되므로 위험 기상 안내나 예보 용도가 아니다. 반올림 위치의 모델 기온은 실제 체감·측정 기온과 다를 수 있다.

## 이용 조건 / 검증 경계

[Open-Meteo 이용 조건](https://open-meteo.com/en/terms)에 따라 교육 / 포트폴리오 비상업 용도로 무료 Endpoint를 사용한다. 무료 사용은 하루 10,000회 미만, 시간당 5,000회, 분당 600회 제한이며 데이터는 CC BY 4.0이다. UI에 **날씨 데이터: Open-Meteo** 링크를 표시한다. 상업 용도나 사용량 확대 시 이용 조건을 다시 검토한다.

실제 위치 조회는 HTTPS 또는 localhost와 브라우저 지원이 필요하다. 자동 재시도·주기 조회는 없다. 테스트는 위치·권한·네트워크 mock을 사용한다. 최종 검증은 Orchestrator Verify이며 실제 브라우저 권한 UI / 390·768·1280px 화면 확인과 Staging 영상은 배포 후 후속 확인이다. 이번 Contract는 `docs/images/`를 허용하지 않아 Repository 캡처 저장은 승인된 후속 작업으로 남긴다.
