## 달라진 점

### 1. 소셜 로그인과 사용자별 기록

- Google / Kakao 계정으로 로그인합니다. "로그인 없이 둘러보기"를 누르면 체험 계정으로 바로 써 볼 수 있습니다.
- 기록이 사용자별로 분리됩니다. 체험 계정의 기록은 모든 방문자가 함께 봅니다.
- 제공자의 사용자 번호와 닉네임만 저장합니다. 이메일과 프로필 사진은 받지 않고, 닉네임 첫 글자로 아바타를 표시합니다.
- 아바타 메뉴에서 로그아웃과 **회원 탈퇴**(계정과 기록 모두 삭제)를 할 수 있습니다.
- 개인정보 처리 안내 화면(`/privacy`)을 추가했습니다.

### 2. AI 코멘트와 주간 리포트

- Check-in을 저장하면 AI가 오늘의 코멘트를 자동으로 씁니다. History에서는 최근 7일을 요약한 주간 리포트를 만들 수 있습니다.
- Score, 기분, 추천은 계속 규칙이 결정합니다. AI는 그 결과를 읽기 쉬운 문장으로 풀어 줄 뿐 판정에 관여하지 않습니다.
- Amazon Bedrock의 Claude Sonnet 5.5를 사용합니다. 이름과 지역 같은 식별 정보는 모델에 보내지 않습니다.
- 소셜 로그인 사용자만 쓸 수 있고 하루 생성 횟수에 제한이 있습니다(코멘트 10회, 리포트 2회). 생성에 실패해도 규칙이 만든 요약 문장은 그대로 보입니다.

### 3. 개인별 평소 값과 신체 긴장도

- 최근 14일 기록이 5건 이상 쌓이면 그 평균을 "평소 값"으로 삼아 오늘 값과 비교합니다. 지표마다 "평소 대비 +14"처럼 차이를 보여 줍니다.
- 심박수가 평소보다 15% 이상, 또는 호흡수가 20% 이상 높으면 신체 긴장도 "높음"으로 표시하고, 기분 판정과 추천을 차분한 쪽으로 조정합니다. Wellness Score는 바꾸지 않습니다.
- 체험 계정은 모든 방문자 기록의 평균과 비교하며, 화면에 그 사실을 안내합니다.

### 4. 추천 다양화와 평가

- 날짜에 따라 추천 후보를 돌려 가며 골라, 같은 상태라도 날마다 다른 음식과 음악이 나옵니다. 선곡 목록도 다듬었습니다.
- 추천마다 좋아요 / 별로예요를 남길 수 있고, 다음 Check-in의 추천에 반영됩니다. 별로예요 항목은 건너뛰고 좋아요 항목은 앞자리에 둡니다.
- 추천 음식에 음식 Emoji가 붙습니다.

### 5. 지역 기록

- 자동 조회한 지역 이름을 기록과 함께 저장해 Dashboard, History, Check-in 결과에서 날씨와 함께 보여 줍니다. 좌표는 저장하지 않습니다.

### 6. 화면 다듬기

- **로그인**: Google / Kakao 버튼에 제공자 Logo와 색을 적용했습니다.
- **Dashboard**: 평가 버튼을 이름 옆의 아이콘으로, 음악 재생을 제목 왼쪽의 재생 아이콘으로 바꿔 추천 영역을 간결하게 했습니다.
- **Check-in**: 날씨 영역을 조회 결과가 먼저 보이게 재배치했습니다. 컨디션은 Slider로도 입력할 수 있습니다. 결과 화면은 Dashboard와 같은 Score / 날씨 Tile을 씁니다.
- **History**: 한 페이지에 5건씩 나누고, 기록마다 추천 이력을 접어 두었습니다. 주간 리포트 기간을 한국어 날짜로 표시합니다.
- **공통**: 모든 화면 아래에 Footer를 두었습니다.

### 7. 배포

- 문서만 바뀐 Commit은 자동 배포를 건너뜁니다.
- OAuth 값과 AI 호출 설정은 Secrets Manager와 Stack Parameter로 주입합니다. 저장소에는 값이 없습니다.
- AI 호출은 별도 AWS 계정의 Role을 임시 자격 증명으로 빌려 씁니다.

## API / Data 변경

- 모든 기록 API가 로그인을 요구합니다. 로그인하지 않으면 `401`을 돌려주고, 변경 요청은 CSRF 값을 확인합니다.
- 추가된 API: 로그인 상태 / 체험 로그인 / 로그아웃 / 계정 삭제(`/api/auth/…`), AI 코멘트(`/api/check-ins/{id}/insight`), 주간 리포트(`/api/reports/weekly`), 추천 평가(`/api/recommendations/feedback`)
- Check-in 응답에 `weather.region`과 `baseline`(평소 값 비교), History 항목에 `region`과 `tension`이 추가됐습니다.
- DB Migration:
  | Version | 내용 |
  |---|---|
  | `V3` | 사용자와 Session Table, 기록의 사용자 연결 |
  | `V4` | 기록의 지역 이름 |
  | `V5` | AI 코멘트 / 주간 리포트 |
  | `V6` | 추천 평가 |
  | `V7` | 평소 값 평균 / 표본 수 / 긴장도 |

## 외부 서비스

| 서비스 | 용도 | 비고 |
|---|---|---|
| Google / Kakao | 로그인 | 사용자 번호와 닉네임만 받음 |
| Amazon Bedrock (Claude Sonnet 5.5) | AI 코멘트 / 주간 리포트 | 식별 정보를 보내지 않음 |
| Open-Meteo, BigDataCloud | 날씨, 지역 이름 | 이전 Version과 같음 |
| YouTube | 추천 음악 재생 | 재생 버튼을 누를 때만 불러옴 |

## 알려진 사항

- 신체 긴장도와 Wellness Score는 서비스용 참고 규칙이며 의학적 기준이 아닙니다.
- 긴장도가 높아 기분이 "균형 있음"으로 낮춰질 때, 요약 문장은 조정 전 기분의 문장에 긴장도 문장을 덧붙입니다.
- 이전 Version에서 만든 기록에는 지역, 긴장도가 없습니다.
- 체험 계정은 추천 평가와 AI 기능을 쓸 수 없습니다.
- 실제 Production 환경은 아직 없습니다. 이 Version은 Staging에서 검증했습니다.
