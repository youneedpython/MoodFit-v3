# MoodFit v3.1.0

**AWS에 실제로 배포하고, `main`에 Merge하면 자동으로 배포되는** 단계까지 온 Release입니다. 개발 방식도 사람이 Agent를 하나씩 실행하던 것에서, 두 Agent(실행 Codex, 검토 Claude)를 Orchestrator가 이어 주는 방식으로 바꿨습니다.

## 달라진 점

### 1. AWS Staging 환경

Production과 같은 구조로 서울 Region에 만들었습니다. 모든 Resource는 CloudFormation Template 8개(`infra/cloudformation/`)로 관리합니다.

| 영역 | 구성 |
|---|---|
| 접속 | Route 53 → CloudFront(HTTPS) → 화면은 비공개 S3, `/api`는 ALB |
| Application | ECS Fargate Task 2개(2개 AZ), Deployment Circuit Breaker로 실패 시 자동 롤백 |
| Database | RDS MySQL 8.4 Multi-AZ, Private Subnet, 자동 백업 14일 |
| Network | VPC, Subnet 3계층(Public / App / DB), NAT Gateway |
| 운영 | ECR(immutable Tag), Secrets Manager, CloudWatch Logs, AWS Budgets |

- ALB는 CloudFront가 붙이는 검증 Header가 없으면 요청을 거부합니다. DB는 외부에서 직접 접근할 수 없습니다.
- 구조 그림과 결정 근거: `docs/13-AWS-ARCHITECTURE.md`, DEC-027

### 2. 자동 배포 (Continuous Deployment)

`main`의 CI가 성공하면 Staging에 자동으로 배포합니다(`.github/workflows/deploy-staging.yml`).

1. Backend Test / Build → Container Image Build
2. GitHub OIDC로 배포 전용 Role의 임시 자격 증명 발급(**AWS Access Key를 저장하지 않습니다**)
3. Image를 Commit SHA Tag로 ECR에 Push → ECS Service 갱신 → 배포 완료 판정
4. Frontend Build → S3 업로드 → CloudFront Cache 무효화
5. 사용자 주소를 대상으로 Smoke Test(Check-in → Dashboard → History)

수동 실행에 이전 Commit SHA를 넣으면 그 Version으로 되돌립니다. 설명: `docs/21-STAGING-CD.md`

### 3. Multi-Agent Orchestrator

`node scripts/orchestrator/run.mjs TASK-XXX` 한 번으로 아래를 이어서 실행합니다.

```text
사전 점검 → 작업 폴더 준비 → Codex 실행 → 변경 범위 / Secret 검사 → 검증(Test, Build) → Claude Review → 판정 → Commit / Push / Draft PR
```

- Task마다 허용 경로와 금지 경로를 적은 Contract(`harness/tasks/`)를 두고, 벗어난 변경은 차단합니다.
- Secret으로 보이는 값이 있으면 멈춥니다. 오탐은 Human이 승인한 문구만 예외로 둡니다.
- Merge는 항상 Human이 합니다. Branch 보호 규칙(Squash Merge만 허용, CI 필수)을 적용했습니다.

### 4. 접근 권한

- AWS: 읽기 전용 / Staging 배포 / Production(Human 전용) 권한을 분리했습니다. Agent는 읽기 전용만 씁니다(DEC-029).
- Stack 변경은 Human이 Change Set으로 내용을 확인한 뒤 실행합니다.

### 5. 위치 인식 + 날씨 자동 조회

Check-in 화면에서 현재 위치의 기온과 날씨를 자동으로 채웁니다(Open-Meteo, API Key 없음). 좌표는 저장하지 않습니다.

### 6. 그 밖의 변경

- Backend Container Image(비 root 사용자, Health Check)와 Container Smoke Test
- Test용 MySQL을 8.4로 맞춤(운영 DB와 같은 Version)
- CI: 실행 시간 제한, 동시 실행 제어, Step Summary 보강

## 첫 자동 배포에서 고친 것

자동 배포는 처음에 두 번 실패했고, 원인을 찾아 고쳤습니다.

- **OIDC 인증 거부**: 이 저장소는 OIDC subject에 숫자 ID가 붙는 형식을 쓰는데, Role의 신뢰 조건은 이름만 있는 형식을 기대했습니다. 신뢰 조건을 실제 형식에 맞췄습니다(TASK-038).
- **배포는 성공했는데 실패로 판정**: 안정화 대기 직후 한 번만 조회해 완료 상태를 검사하던 것을, 일정 시간 반복 조회하는 방식으로 바꿨습니다. 롤백은 계속 실패로 처리합니다(TASK-039).
